# RESULTS - 数字的唯一来源

每条都标日期、提交、电源态与配置。跨行比较前先确认口径相同（见 `README.md`）。
新数字往本文件加，不要新开文档；design 引用的每个实测数字都必须在这里有回链。

口径：`Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf`（21.28 GiB，arch `qwen35moe`，40 主层 + 1 MTP 层，256 专家 top-8），
10K prompt，ctx 256K，greedy，单流，平衡 + AC，dGPU 独占。

## 1. 张量账（M0-1，2026-10-24）

来源：`ggufsize.py` 直接解析 GGUF 张量表，无推理。

| 类别 | 大小 | 每 token 读取 |
|---|---:|---|
| routed_experts（Q4_K 11520 块、Q5_K 7040 块、Q6_K 630 块） | 18.74 GiB | 只读 top-8 |
| dense_other（attention / DeltaNet / 路由器 / 归一化） | 1.39 GiB | 全量 |
| output 头（Q8_0） | 0.50 GiB | 全量 |
| shared_expert（Q8_0） | 0.13 GiB | 全量 |
| token_embd（Q8_0） | 0.50 GiB | 否（只查一行） |
| nextn（MTP 块，Q8_0） | 8 MiB | 草稿时读取 |

- 专家 FFN 维 512，hidden 2048，每个专家约 **1.84 MiB**（41 x 256 个专家摊平）。
- 稠密每 token 读取：2.02 GiB ≈ **2.17 GB**。
- 专家每 token 读取：8 x 40 x 1.84 MiB ≈ **0.62 GB**。

## 2. 路由 trace 的局部性与命中率（M0-2，2026-10-24）

数据：`bench/raw/m0-qwen36/trace-10k-g128.bin`（10K prompt + 128 token greedy，CPU 后端 cb_eval 回调），
模拟：`bench/raw/m0-qwen36/m0-sim.py`，输出 `m0-sim-10k.txt`。
**统计只用 30 个完整记录的 DeltaNet 层**（10 个 full-attention 层在解码阶段无回调，见第 6 节缺口）。

| 指标 | 实测 |
|---|---|
| 与上一 token 同专家的比例 reuse(t-1) | 56.8% |
| 连续 w 个解码 token 的唯一专家数/层（w=1/2/4/8） | 8.0 / 11.5 / 16.4 / 23.3 |
| 同口径随机路由期望（w=2/4/8） | 15.8 / 30.5 / 57.4 |

| 缓存占比（39 层 9984 专家） | 容量 | 解码命中（prefill 预热 LRU） | 冷启动 LRU（不预热） |
|---|---:|---:|---:|
| 10% | 1.78 GiB | 96.8% | 62.1% |
| 20% | 3.57 GiB | 97.4% | 79.5% |
| 25% | 4.46 GiB | 97.9% | - |
| 30% | 5.35 GiB | 98.2% | - |

- 对照：静态 top-N（按 prefill 频次固定）在 25% 只有 46.1%。**命中来自时间局部性，静态驻留不可取。**
- 换文本复测（13 份技术文档拼接，`prompt-multidoc10k.txt`，9402 token）：25% 命中 97.8%（原 97.9%）、
  w=8 唯一专家 23.4（原 23.3）、reuse 57.0%（原 56.8%）。两份都是技术文本，仍未覆盖对话/代码/多语言。

## 3. MTP 接受率（M1，完整词表，2026-10-24）

命令：`llama-cli --spec-type draft-mtp`，10K prompt（`prompt10k.txt`），greedy，`--cpu-moe` 配置。
默认深度那一轮生成 128 token，n-max 4 / 8 两轮生成 256 token。
**速度数字（14.4 tok/s）来自 `--cpu-moe`，不代表目标配置，不得用于性能结论。**

| `--spec-draft-n-max` | 草稿数 | 接受数 | 单草稿接受率 | 周期数（推算） | 每周期产出 E |
|---|---:|---:|---:|---:|---:|
| 默认（约 3），128 token | 130 | 83 | 63.8% | 45 | 2.84 |
| 4，256 token | 310 | 177 | 57.1% | 79 | 3.24 |
| 8，256 token | 519 | 189 | 36.4% | 67 | 3.82 |

- 周期数 = 生成 token 数 - 接受数（每周期产出"接受数 + 1"，含 bonus），是推算值，日志无直接计数。
  三行分别是 128 - 83 = 45、256 - 177 = 79、256 - 189 = 67，与 E 的定义自洽。
- 草稿数/周期：k=4 约 3.9，k=8 约 7.7，与推算一致。
- 默认草稿深度约 3，不是 1：早期把 0.64 当单位置接受率是错的（design 2.4）。

## 4. 完整词表草稿的修正投影（推算，不是实测）

周期时间 = 验证 pass + 草稿步数 x 2.3 ms（每步一次完整输出头，0.5 GB / 217 GB/s）+ 未命中 H2D 约 1-1.5 ms。
验证 pass 取 design 6.2（k=3 约 15 ms，k=4 约 15.9 ms，k=8 约 18.3 ms）。

| 配置 | 草稿/周期 | E（实测） | 周期时间（估） | TG（估） | >= 130 |
|---|---:|---:|---:|---:|---|
| 默认深度，完整词表 | 2.9 | 2.84 | 22.4 ms | 127 | 否 |
| n-max 4，完整词表 | 3.9 | 3.24 | 25.9 ms | 125 | 否 |
| n-max 8，完整词表 | 7.7 | 3.82 | 37.5 ms | 102 | 否 |
| 默认深度，受限词表（假设 E 不变） | 2.9 | 2.84 | 16.1 ms | 176 | 是 |

- 受限词表把草稿代价降到约 0.15 ms/步；达到 130 只需 E >= 2.1（默认深度）或 2.3（n-max 4），
  相对已测的 2.84 / 3.24 有约 25-30% 的接受率余量。余量是否真实，取决于 M1-3 的实测。
- 周期时间是模型估计，误差可能 +/-10%，M1-4 必须用真实 Vulkan 路径复核。

## 5. 带宽与地板（同机实测，2026-10-20/21；M1-5 复测前沿用）

| 量 | 值 | 出处 | 日期 |

- M1-5 负责同口径复测；任一项偏差 > 5% 要改 design 第 1.3 / 6 节的引用。

## 6. 已知缺口（不得当成结论）

1. 10 个 full-attention 层的解码路由缺失（M1-1），所以第 2 节的 U_k 与命中率只覆盖 30/40 层。
2. layer 39 在 prefill 里只有 21 个 token（输出被裁剪），已排除。
3. 两份 prompt 都是技术文本，非技术文本的局部性未测（M1-2）。
4. 带宽数字未在新模型上复测（M1-5）。
5. 受限词表的 E 未测（M1-3），所以第 4 节最后一行是假设。
