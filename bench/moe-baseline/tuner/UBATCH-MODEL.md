# 从测量推导 ubatch（GPU / 带宽 / 模型 的对应关系）

结论先行：**最优 ubatch 不是常数，而是"权重字节 / 每 token 计算 × 机器算力带宽比"推出的拐点**。
本文件给出模型、拟合结果，以及本机（RX 6700S / Vulkan / Ornith-1.5-35B-A3B Q4_K）的实测参数。

## 1. 模型

单趟 prefill（prompt = ubatch = M，一次前向）的吞吐：

```
T(M) = M / (A + B*M)        [tokens/s]
1/T  = B + A*(1/M)          -> 对 1/M 线性，最小二乘拟合
```

- `A = 权重字节 / BW_eff`：**每趟把所有专家读一次**的时间（与 M 无关）
- `B = 每 token FLOPs / FLOPS_eff`：每 token 计算时间
- 拐点 `M* = A / B`：内存项 = 算力项；**M ≥ M\* 才进入算力平台**（否则每 token 都在"分摊一次权重读"）

由环境量表达：

```
A = W / BW_eff
B = 2 * P_active / FLOPS_eff
=>  M* = A/B = ( W / (2 * P_active) ) * ( FLOPS_eff / BW_eff )
```

即 **M\* = 模型的"计算强度倒数" × 机器的"算力带宽比"**：
- `W` = 每次前向要读的权重字节（MoE prefill 时≈整个模型文件大小，因为大 batch 命中全部专家）
- `P_active` = 每 token 激活参数
- `BW_eff` / `FLOPS_eff` = **有效**带宽/算力（含后端效率与 CPU/GPU 分工，远低于峰值）

**可迁移性**：换 GPU 或模型时，只需重新测 `BW_eff`、`FLOPS_eff`（两三个 ubatch 点即可拟合），
`M*` 随之改变，无需人工拍值。

## 2. 本机实测拟合（`-dev Vulkan1 -ngl 99 -ncmoe 27 -fa on`，Q4_K，W=20.21 GiB）

单趟扫描（`-p M -ub M -n 0`）：

| M | PP (t/s) |
|---:|---:|
| 128 | 39.98 |
| 256 | 70.39 |
| 512 | 138.50 |
| 1024 | **66.79** ← 异常（见 §4） |
| 1536 | 284.58 |
| 2048 | 317.55 |

拟合（排除异常点 1024）：

| 量 | 值 | 含义 |
|---|---|---|
| `A` | 3.02 s | 每趟权重读时间 |
| `B` | 1.666 ms/token | 每 token 计算 |
| **`M* = A/B`** | **≈1814 tokens** | 拐点 |
| `BW_eff` | 7.2 GB/s | 峰值的 3.2%（RDNA2 224 GB/s） |
| `FLOPS_eff` | 2.88 TFLOP/s | 峰值的 18%（≈16 TFLOP/s） |

**验证**（模型预测 vs 实测）：
`M=256 -> 74 (实测 70)`、`M=512 -> 132 (139)`、`M=2048 -> 318 (318)`。吻合。

**推论**：本机 `M* ≈ 1800`，所以 **ubatch 应取 ~2048**（即最接近且不小于 M\* 的、能装进显存的档位）。

## 3. 用它给出推荐值

```
M_recommended = clamp( M*, grid_min, min(M_vram, M_attn) )
```
- `M*`：上面的拐点（纯吞吐）。
- `M_vram`：compute buffer + KV 能容纳的最大 ubatch（本机 ub4096 因内存压力退化）。
- `M_attn`：**注意力 O(n²)** 上限。本机实测 prompt 从 2048 增到 4096/8192 时 PP 回落到 82/75 t/s，
  所以**即使 M\* 允许，M_attn 也把有效 ubatch 压回 ~2048**。

本机：`M* ≈ 1814`，`M_attn ≈ 2048` -> **推荐 2048**。

## 4. 重要发现：并非所有 ubatch 等价

`M=1024` 实测 66.79 t/s，显著差于 512(138) 与 1536(285)，且 `±1.48` 很窄（非噪声）。
这解释了为什么"扫描若干点再拟合"优于"拍一个值"：**某些 ubatch 会落到病态路径**（缓冲区/kernel 分块边界等），
拟合时必须识别并排除，推荐时也应避开这些档位。

## 5. 与调优服务的衔接

`tuner/tune.ps1` 自动做单趟扫描 -> 拟合 `A、B、M*、BW_eff` -> 由 `M*` 与实测网格给出推荐 ubatch，
连同 `-ncmoe` 驻留扫描一起持久化到 `store/<gpu>__<model>.json`；换硬件/模型后重跑即可，
不需要人工重新估 M\*。
