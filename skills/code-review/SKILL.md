# qwen36 运行时实现审查

本文件是仓库内按需读取的检查表，不代表已经运行审查或测试。先读根 `AGENTS.md`；涉及 runtime 时读 `runtime/AGENTS.md`，判门禁读 `docs/agent/gates.md`。

这是专用运行时重写，不是上游贡献。不要套用上游的先开 issue、先支持 CPU、必须覆盖其它后端、禁止模型专用 CLI 等准入规则；不要为审查主动联网。目标、模块边界和权限以本项目文档为准。

## 1. 定位范围与完成条件

- 先看工作区状态和本任务 diff，只审当前请求涉及的增量；不要默认审整条分支，也不覆盖他人未提交改动。
- 将 `done_when` 拆成可验证条目，逐条对应现有命令、输入、预期输出和权威阈值；没有检查器的条目先补检查，不能写成 n-a。
- 读完整的被改函数、直接调用者、被调用实现和测试参考，而不止搜索命中片段。追到实际 CLI/模型入口，确认新代码可达、参数确实传下去。
- 区分设计约束、实现事实和待证假设。按 evidence/slug 查相关旧失败；参考实现也要查版本、适用模型及差异，不能因为来自 CPU/fork 就认定正确。

## 2. 写之前：契约和证伪

- 数值接口核对 shape、维序/stride、量化块与符号、head 映射、缩放/归一化/epsilon、位置和 causal mask；状态接口核对初始化、跨 chunk 保存、重置与回滚。
- 资源接口核对所有权、源缓冲存活期、上传/回读、descriptor 生命周期、barrier/fence 以及 CPU/GPU 部分输出合并时点；不得靠异步执行顺序猜正确性。
- 用现有接口/测试中的断言和非对称样例固定契约，不另建大篇设计文档或第二套调度器。
- 缺陷修复先重现失败；为主要假设写可区分预期。优先定位第一处偏差，禁止只看末端 PPL/吞吐就调参数。
- CPU 双精度参考从原始输入独立计算，不复制 shader 的打包表达式、索引公式或近似算法。可用手算、逐字节解码、穷举码值或不同表达核对参考。
- 设备中间量可作为局部定位输入，但不能冒充独立端到端参考；两份代码同错也会全绿。

## 3. 改之后：真实路径和反例

- 检查真实生产入口，而非测试独自拼参数或重新上传一份正确权重。CLI 选项必须一路传到执行点；用可观察差异证明，而非只测解析。
- 修复对应的回归要能证明旧实现失败、新实现通过。若无法安全重放旧实现，明确缺口并用隔离反例证明检测能力，禁止破坏工作区来制造红灯。
- 针对变化选择边界：非对称轴、多 head/token、量化正负边界、尾块、连续 dispatch、复用/释放、空/坏输入。不要写永远只测对称数据的测试。
- 局部内核过后检查消费者串联；涉及状态时覆盖多次调用、跨 chunk 边界、reset/rollback 和前缀因果性。测试原始输入到最终输出，不只测每段各自正确。
- 多执行路径先检查输出一致，再比较速度；性能对照遵守相同输入、预热和口径，不把短输入诊断当正式档位。

## 4. 安全与维护成本

- 在 GGUF、CLI、文件等外部边界验证类型、长度、维度及索引；乘法/对齐前检查溢出，不能先分配再检查。
- 检查临时向量、映射和异步缓冲生命周期；运行期容量不足走既定错误/降级路径，不用 `GGML_ABORT`。
- 不引入不需要的依赖、泛化层或重复缓存/预算器。修复不加保留错误行为的开关；实验/优化策略按项目开关规则隔离。
- 代码只用 ASCII，沿用现有命名/缩进，注释只写非显然原因；不以风格整理扩大缺陷修复范围。

## 5. 判定与后续动作

- 核对实际构建目标、二进制路径、命令退出码、原始产物和断言。测试程序返回 PASS 不代表已满足更严格的 L-KERN/L-MODEL。
- 每项结论标明文件位置、失败条件、影响及证据；证据不足写未验证。按正确性/安全阻断、覆盖缺口、非阻断维护项排序。
- 实施任务的自审发现可修问题，就修复并重跑，不止输出建议等用户批准；仅审查请求则保持只读。
- 如分派独立审查，给出契约、diff、实际命令和已知缺口；主 agent 复核修改与证据。子 agent 的完成摘要不是验收证明。
- 输出仅总结已验证结果和剩余阻断，不虚报门禁，不自动提交、推送或发布评论。
